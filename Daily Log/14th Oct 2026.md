## 5. Bugs found and fixed (all tested)

1. **🔴 CMS duplicate filing** (`server/cms.py`)
   - **Cause:** the CMS replied HTTP **202**, and the code treated only 200/201 as success. The retry queue then filed the same complaint again, creating **CZ000327, CZ000328 and CZ000329** (the original is CZ000326).
   - **Fix:** any 2xx response with a complaint number counts as success, and retries check the database first. The server was restarted before a 4th retry.
   - **Test:** `scripts/cms_response_test.py`.
2. **STT going deaf mid-call** (`server/stt_watchdog.py`, new)
   - If the caller speaks and no transcript arrives for 8 s, the bot reconnects to Sarvam. Added after call `e60c27bf`.
3. **Watchdog crashed on every turn** (call `3d22c658`)
   - **Cause:** Pipecat replaces an internal variable called `_clock` at startup, which the watchdog also used.
   - **Effect:** the crash also dropped the "caller stopped" signal, so Sarvam never got its `flush()` and every transcript came slower.
   - **Fix:** renamed the variable, plus a test that reproduces Pipecat's setup.
4. **Latency timer only measured 1 of 17 replies** (`server/latency.py`)
   - **Cause:** Pipecat's speech-detector events travel upstream, and the latency observer only watches downstream.
   - **Fix:** catch those events in either direction.
5. **Short answers lost** (call `c76a31a6`: "हो" twice, 25 s stall)
   - **Cause:** Sarvam only finishes a transcript quickly when it gets a `flush()`. That's sent only when Silero detects you stopped, and Silero fired just **3 times in the whole call** (short words on phone audio score 0.14–0.56).
   - **Fix:** also flush on loudness: a burst of voice followed by quiet.
6. **That flush then cut sentences into fragments** (call `6dda3e2c`)
   - **Effect:** after 0.4 s of quiet it fired mid-sentence, so one description became **6 pieces in 7 s**, each cancelling the reply being prepared. The bot answered ~10 s late.
   - **Fix:** raised to **0.8 s**, tested on the recording: 1 cut instead of 4, and all real answers still flushed.
7. **Transcript not saved with Gemini** (`server/bot.py`)
   - **Cause:** Gemini adds context entries in its own format, and the save code crashed on them.
   - **Effect:** the post-call address review also didn't run for that call. Fixed.
8. **Voice breaking on the phone** (call `6dda3e2c`; your recording was used as evidence)
   - **Cause:** the phone line is narrowband (nothing above 3.4 kHz). Freddie at 24 kHz peaked at 100% (**113 clipped samples on the handset**) and had 24× Sarvam's high-frequency energy.
   - **Fix:** Murf now renders at **8 kHz**, at **70% volume** (`MURF_GAIN=0.7`).
   - **Measured:** peak 97.5% → 70%; energy above 4 kHz 3.87% → 0.00%.
9. **Smaller fixes:**
   - `/health` now shows the active TTS provider.
   - The audio-cache warm-up now works with Murf.
   - Missing-key warnings now cover Murf and Google.
   - Three tests now pin the Sarvam provider they check.

**New setting:** `STT_TTFS_P99`. The bot waits a fixed **0.97 s after every transcript** before replying (Pipecat's fallback timer; Smart Turn effectively never decides). This setting can shorten that wait. It's added but **not turned on yet**.
